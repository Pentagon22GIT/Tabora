# アーキテクチャ

この文書は、SnapFlow Final Baselineから継承したTaboraの構造と、v1系の安定化、およびv2.0.0以降のSpace membership観測・Mission Controlグループ移送を説明するものです。これは実装の説明文書であり、実コードとは別の新しい挙動を定義するものではありません。

## アプリケーション起動と設定

- `AppMain.swift` はメニューバーアプリのライフサイクル、メニューコマンド、グローバルショートカット登録、更新リンクの表示、Accessibility設定への導線を管理します。
- `AppSettings.swift` は現在のアプリの `UserDefaults.standard` domainへscalarなユーザー設定を保存し、`ServiceManagement` を使ってログイン項目登録を管理します。
- `Localization.swift` は対応言語、初回言語決定、保存、resource bundle解決、日本語fallbackを一つの境界へ集約します。初回だけmacOSの最優先言語を参照し、以後は保存した`appLanguage`を使用します。不正値とresource欠落は日本語へfail closedします。
- `ConstraintStore.swift` はアプリ別App Constraint recordをschema version付きJSONとしてApplication SupportのBundle ID別directoryへatomic writeします。Official / Community間でrecordを暗黙共有せず、record単位でvalidationして1 recordの破損を他recordの消失へ波及させません。
- `SettingsWindowController.swift` は上部固定のカテゴリ切替で一般 / コマンド / サイズ制約 / 試験的機能を表示し、「アプリ別のサイズ制約」でApp Constraintの記録許可・読み取り専用の値表示・明示計測・record削除をローカルstoreへ反映します。手動の数値編集経路は持ちません。一般設定の言語選択では適用ボタンだけを選択先言語で即時表示し、明示計測中は再起動を拒否します。
- 言語適用は現在process内でUI objectを部分的に差し替えません。`AppMain.swift`が同じ`.app` bundleだけを対象にrelaunch helperを起動できた場合に限り選択を保存し、現在processを終了します。helperは親processの終了を有限時間確認してから`/usr/bin/open -g`を実行します。起動失敗時は保存も終了も行いません。この再起動境界はSnap / Group / Resize / Recovery / Mission Control stateへ新しいmutation経路を追加しません。
- 2 / 3 / 4分割Assist切り替えは初期OFFです。隣接Quarterが2枚配置されたsession、または単一Halfから反対側を異なる2windowへ分割可能なsessionだけ、Picker表示中にcombined-sessionのOption状態を約60 Hzで確認します。通常コマンド用Carbon HotKeyやkeyboard event経路には登録せず、Option eventも消費しません。session終了、cancel、drag、shared resize、Space/display遷移、設定OFFではtimerを即時解除します。

## ウィンドウ観測とidentity

- `AXWindowService.swift` はAccessibilityによる観測とWindow Server identityを組み合わせます。
- `WindowSafetyPolicies.swift` は、一時的な観測失敗とconfirmed disappearanceを区別するための安全state / authorization policyを保持します。
- physicalなWindow Server surfaceを特定する必要がある場面ではPID + CGWindowIDを使用し、AX geometryはmutationおよびnative resizeのgeometry domainとして扱います。
- `AppConstraintIdentityResolver.swift` はruntime window identityとは独立したpersistent app identityを解決します。native appはBundle ID + Designated Requirement、Chrome Web Appはparent Chrome code identity + canonical Web App IDへ束縛し、PID / CGWindowID / AX element hash / version / pathをpersistent keyにしません。

## Placementとsnap制御

- `SnapController.swift` はdrag観測、snap選択、Assist、restore state、Recovery、高位アプリstateを統括します。
- `SnapZone.swift` と `SplitLayout.swift` はtarget zoneとlayout関係をモデル化します。
- placement logicは3分割専用分岐ではなく、2 / 3 / 4 window構成へ共通の構造規則を適用します。
- v1.0.1では、既存groupの複数memberを一度に置き換える場合だけ、displaced partitionとretained partitionの共有境界が同一axis・同一coordinate上で連続した一本の直線として成立することをplacement認可条件へ追加します。
- single-member replacementは従来経路を維持します。multi-member replacementが不適格な場合は、そのgroupに対するreplacement / extensionを認可せず、既存のindependent split判定へ戻します。
- multi-member replacementの認可はmutation開始前に行い、commit直前には対象groupのrevision、member集合、AX current frameだけを局所再検証します。再検証失敗はfail-closedとし、new-group fallbackへ変換しません。
- v1.1.0ではknown App ConstraintをAX mutation前に`SplitLayoutGeometry.allowedBoundaryRange`へ合成します。shared boundaryへ参加するwindowのmin/max不等式を2 / 3 / 4共通トポロジーでintersectionし、feasibleならrequested boundaryを合法範囲へclamp、infeasibleならprovisional group / toggle / proxyをcommitしません。Previewとinitial placementは同じgeometry planを使用します。
- placement authorizationでは、App Constraint適用後のruntime frameがnominal 50%境界へ既に接触していることを要求しません。incoming zoneと既存layout zoneからproposed shared-boundary topologyを作り、そのtopologyを対象にknown constraintを解きます。live handle / group validationは引き続き実frameから行い、proposed topologyをauthoritative runtime existence evidenceには使いません。
- v1.1.0のfull-group replacementは、incoming zoneが既存groupのlogical cellsを完全一致で覆い、commit直前のgroup revision / member集合 / AX current frame再検証にも成功した場合だけ認可します。この場合だけ旧groupを共通Atomic Group Departureで完全retireし、incomingはprovisional singleとして開始します。部分重なりを理由にgroup全体を壊しません。
- Mission Control PreviewのHOT/COLDはGroup単位で管理しますが、前面証拠はmember単位のphysical surfaceから作ります。completeなon-screen Window Server observationで全exact memberが可視なら、各member自身より前に実際に交差する外部layer-0 surfaceだけをoccluder候補とし、Group内member同士のorderingとunion boundsの空白は外部occlusionとして扱いません。対象geometryはGroupの物理Display frame内へscopeし、共有Window Server snapshotの既存1 pt境界許容を隣接Displayの偽occlusionへ変換しません。
- Previewのoccluder候補は候補PID内だけで限定的にAX意味分類します。`AXStandardWindow`のnon-modal contentは通常occluder、`AXDialog` / `AXSystemDialog` / modal / exact attached sheetはauxiliaryです。未知・独自subroleや一時的なAX解決失敗はauxiliaryと断定せず`UNKNOWN`に残し、exact candidate単位のsemantic evidenceとGroup単位の有限physical-occlusion budgetを分離します。候補identityが入れ替わっても確認を無期限に継続せず、明示的auxiliary証拠がない連続occlusionはbounded fallbackでCOLDへ収束します。
- complete observationで全memberがon-screen censusから外れた場合は`COLD-not-visible`としてHOT leaseを終了し、不可視化だけでは最終画像を取得しません。部分member・incomplete observation・desktop transform中は`indeterminate`として直前状態を破壊しません。HOT→`COLD-visible`だけを2観測・0.15秒以上で確定して`coldConfirmed`取得へ接続し、not-visible境界では旧visible epochのCOLD commit authorizationだけを失効します。`geometryConfirmed`は独立して維持します。
- trigger取得はglobal admission（outstanding最大4件、OperationQueue最大8件）へ通します。上限到達時もactiveな待機要求は物理window単位で保持し、display間round-robin・display内FIFOで空きへ投入します。generic proxy updateやcache ageは画像要求を生成しません。
- login session非アクティブ中はpreview captureとforeground selection観測を停止します。Recovery coreのevent monitor rearmは維持し、復帰後はgenerationを更新して古い派生結果を拒否します。
- Assist pickerのpreview loaderは32 MiBの画像budgetをユニーク候補数で分割し、枚数を理由に候補を打ち切りません。hide時はqueued workとcallback ownershipを破棄します。Window Serverが有限retry後も取得元画像を返さない場合のみ、既存のicon/placeholder表示へfallbackします。
- Assistの候補除外はplacement開始時snapshotを永続的な権威にせず、replacement commit後のcurrent lock / explicit-group stateで再評価します。
- v1.2.0のAssist variantは、隣接Quarterが2枚確定した時にOption中だけ残り2面を通常Halfへ統合します。v2.0.0では逆方向も追加し、単一Halfだけが確定した時、反対側の2 Quarterへ異なる2windowを割り当て可能ならOption中だけ分割表示します。どちらもPanel geometryだけをanimationなしで差し替え、同じpreview loader/cacheを保持します。分割側を1枚選ぶと既存3分割sessionへ合流し、残り1枠に候補がなければ通常Assistと同じ終了経路を通ります。window mutation、App Constraint、group reconcile、shared resizeに専用経路は追加しません。
- 上端maximizeのplacementは元frameへのrestoreと既存split groupのocclusionを管理する独立layerであり、Assistではsplit予約として扱いません。候補選択後の通常Snap commitがmaximize layerを解除するため、候補表示だけを理由にframeやgroup stateを先行変更しません。
- Mission Control previewはmember size-keyまたはdisplay変更を、最後の変化から0.15秒後の一回再観測へdebounceします。同じ最新geometryを2回観測するまで取得せず、物理windowごとに確認候補と待機要求を各1件へ合流します。resize後のfresh captureを待つ間は継承した旧画像を全面投影し、Assist／Snap中はgeometry取得を開始しません。Preview OFFはpresentation updateと独立してcapture generation、待機Operation、request、確認候補、staging、cacheを失効します。

## 明示的groupとresize

- `SnapGroup.swift` は永続的なgroup関係とgroup-level stateをモデル化します。
- `SnapController+ExplicitGroups.swift` はgroup membershipと構造変化をreconcileします。
- `SnapController+HandleResize.swift`、`ResizeHandleOverlay.swift`、`ResizeHandleGeometry.swift` はshared resizeのpresentationとinteractionを担当します。junctionを交点のsingle ownerとし、single-axis boundary control / hit region / hover / cursorはjunction exclusion zone外の同一free interval geometryから生成します。
- valid groupがhandle-presentableなのにexpected handleが表示されない場合はpresentation liveness debtとして扱います。bounded fast retryで解決しないdebtだけを既存1 Hz Recoveryへhandoffし、structural group membershipとは分離します。
- `SnapController+NativeResize.swift` は、本来のnative resize / departureとTabora-owned shared resizeを区別します。
- `SnapController+ExplicitGroups.swift` はgroup departureの認可とcleanup commitを分離します。認可済みdepartureでは対象groupのplacement / restore / resize session / scheduler generation / handle / hit region / cursor / Mission Control proxy等をgroup-localにretireします。shared resize interaction終了が一時的に隠していた無関係groupのhandleは同じdeparture commit内で再構築し、Recovery待ちにしません。
- `LiveResizeScheduler.swift` はlive resize requestをcoalesceし、stale targetが蓄積しないようにします。
- `VirtualResizeOverlay.swift` は軽量なresize presentationを提供します。

## App Constraint

- `AppConstraintModels.swift` は4 bound (`minWidth / minHeight / maxWidth / maxHeight`) のunknown / candidate / known、アプリ単位のRecordingPermission、persistent identityをモデル化します。
- `ConstraintProbe.swift` はTaboraが実際に送ったAX mutationのrequested frameとsettle後accepted frameを比較し、screen / system / peer constraint / AX failure / orthogonal ambiguityを除外した`confirmedAppRejection`だけを学習・constraint由来departureの根拠にします。通常resize履歴は学習しません。
- `ConstraintStore.swift` 内のregistryはknownだけをactive solverへ公開し、candidateをactive geometryへ入れません。known contradictionはpersistent knownを上書きせず、session-onlyの厳しいoverrideとして次interactionへ反映します。
- shared resize sessionはdrag開始時のregistry generationとlegal rangeへ固定します。drag中のpermission / measurement変更で境界rangeをジャンプさせず、次interactionから新constraintを使用します。
- `ConstraintMeasurementEngine.swift` はユーザーが「サイズを取得」を明示実行した場合、またはサイズ差の許可画面で「取得する」を選んだ場合だけ、取得可能な4 boundを軸ごとに測定します。同一アプリにeligible windowが複数ある通常の設定経路ではユーザーが計測対象を選択し、スナップ由来の許可経路ではそのexact triggering windowだけを再検証して使用します。各測定前後にoriginal frame復元を試み、screen usable edgeへ到達しただけのmaximumや曖昧な結果をknownへしません。explicit measurementでunknownだっただけでは既存knownを削除しません。進捗は固定の非modal panelへ表示し、物理復元完了時にinteraction suppressionを解除した後、同じpanelを結果表示へ切り替えてユーザーの「完了」操作まで保持します。
- 初回スナップのoperation-local alternativeは現在の配置の再計画と許可UIの先行予約にだけ使用できます。screen / system limitを除外できない差は対象外とし、この段階ではconstraint値を永続化せずgroup departureも認可しません。persistent learningとconstraint由来departureは従来どおりbounded settlement後の`confirmedAppRejection`だけが認可し、許可後に実行した全辺明示計測だけが追加のknown値を書き込みます。
- App Constraint lifecycleは起動時とapplication launch / terminate eventでrecord単位に再評価します。matching identityの実観測は既存recordをsilent reactivateし、署名不一致またはこのprocessで観測済みのbundle消失だけをdormant根拠にします。LaunchServicesの一時的不確実性は`unknown`として既存lifecycle stateを変更しません。
- commit済みgroupのshared resize中に`confirmedAppRejection`が発生した場合、accepted current frameを残したままgroup relationshipだけをatomic departureでretireします。AX timeout / liveness unknownだけではgroupを破壊しません。

## ForegroundとMission Control

- connected Groupのforeground判定はPreviewのsemantic HOT/COLDとは分離し、従来のstrict Group orderingを維持します。Group member間に同一Display上の外部surfaceが挟まる場合や、外部windowが実際にGroupのDisplayへ跨ぐ場合は引き続きraise対象です。一方、共有1 pt境界許容だけで隣接Displayのwindowが交差したように見えるケースは、対象Groupの`screen.frame`内へgeometryをclipして除外します。plain click時のwhole-group raiseとprovisional Snap peer前面判定は同じphysical Display scopeを使用し、条件を緩めず不要なcross-display mutationだけを防ぎます。

- v2.0.0のSpace関連処理は`WindowSpaces`、`GroupSpaceMigration`、`TaboraSkyLightBridge`へ分離します。`SnapController`は既存状態との接続点だけを保持し、private symbol、selector、ABIを直接参照しません。
- `SkyLightWindowSpaceBackend`はWindow→Space観測とbridged move dispatchだけを担当します。dispatch成功を物理移送成功とはみなさず、`GroupSpaceMigrationLine`が全memberのdestination membershipを再観測します。Proxy dropのdestinationとexact member/layoutはMission Control内でgroup単位にcaptureしますが、private moveはMission Control自身のmanaged-window transform終了を2回・0.15秒以上確認してからFIFOで一件ずつ発行します。対象groupがSpace分離していても少なくとも1 memberの通常geometryを強い終了証拠にでき、全memberが非activeならActive Space通知なしに推測しません。複数groupを同じMission Control sessionで受け付けてもWindowServer operation、membership検証、AX layoutは並列化しません。
- destination layoutのAX mutationはPIDごとのlaneで実行します。同一アプリの複数windowは直列、異なるアプリは並列とし、各windowは既存の有限`setFrameReliably`をそのまま使用します。batch期限切れまたは環境失効時は実行中memberのframe generationを先に取り消し、古いcallbackが次のlane memberを開始できない状態にしてから復元または解散へhandoffします。これはAX書き込み順の競合を避ける実行順序であり、layout plannerや2 / 3 / 4 group geometryを変更しません。
- 通常のSpace分離は`knownSame / knownDifferent / unknown`の三値です。確定した外部分離だけを二回の安定観測後にatomic group departureへ渡し、`unknown`ではグループを破棄しません。private観測能力がない環境だけ、従来のWindow Server / AX間接判定へ戻ります。
- `SLSCopyManagedDisplaySpaces`のread-only topologyは、各managed displayのCurrent SpaceとSpace集合を観測する補助証拠です。Display消失時は旧display所属groupを構造的に保持し、全memberが同一user Space・同一物理NSScreenへ収束し、そのSpaceのmanaged-display識別も一致し、既存zone関係のcomplete connected geometryを維持している場合だけenvironment rebindします。完全検証済みrebindでは旧display由来のdegraded stateと短期confirmation evidenceを同じcommitで解消しますが、別transactionが所有するSpace transition suspensionは維持します。分散/unknownではwindow移動もgroup解散も行いません。
- Proxy移送とProxy選択は別認可です。ドロップはfocus / AXRaiseを行いません。通常Proxy選択は既存foreground transactionを使います。capture済みの「移動準備中／移動待機」Proxyを明示選択した場合だけ、transportとは独立したpost-migration foreground intentを記録し、当該groupの成功と全FIFO terminal後に一度だけ実行します。通常Proxyのconfirmation / activationが存在する間はflushを開始せず、そのtransactionのterminalから再評価します。複数intentは選択順に処理し、最後に選択されたgroupを最後にraiseします。失敗・rollback・source取消ではintentを破棄し、通常foreground modeは変更しません。controller/session停止、機能OFF、reset、wake、display topology変更ではintentとschedule済みflushをgenerationごと無効化し、旧environmentのクリックを後から再生しません。
- 移送captureからterminalまで通常Desktopのfocus/fallback通知はconnected group raiseを開始できません。入口で既存の保留raiseとfallback baselineを破棄し、移送前の選択を後続Spaceで再生しません。明示的な別Proxy選択は固有のMission Control selection transactionで処理し、この一般fallback制限から推測して認可しません。
- 移送中は`GroupSpaceMigrationLine`が唯一の所有者です。`awaitingNormalDesktopDispatch`の各groupは移動済みProxyのgeometryを固定し、暗転した受付済み表示だけを更新します。この状態は実move前なのでcancel時にrollback APIを発行しません。同じgroupの二重captureを拒否し、別groupはstable member IDと物理Window IDが待機列内で重ならない場合だけFIFOへ追加します。destination dispatch直前に各memberの実行時originを記録し、全memberの到達前に失敗した場合はTaboraが動かしたmemberだけをorigin Spaceごとの直列batchで復元します。全member確認後は不可逆なphysical commitとして、後続失敗でもSpaceを戻しません。layoutまたはgroup再構成が失敗した場合はdestination entry frameへのgeometry復元を試み、グループだけを解散します。
- Active Space変更は移送の正常な途中イベントです。`dispatchingMove`から`rebuildingGroup`またはrollback完了まではmigrationがAX frame-operationを所有し、Space変更共通cleanupの`cancelAllFrameOperations()`から除外します。dispatch直前にはstable identity、capture済みWindow ID、単一user Space membershipを全memberで再検証します。memberがsource以外へ個別移動済みでもexact physical surfaceなら現在地からdestinationへ集約し、既にdestinationにいるmemberはmove対象から除外します。全memberがdestinationならprivate moveを重複発行せず、既存layout/commitだけを続行します。Window ID変更、non-user Space、unknownは推測せず拒否または有限再観測します。
- Snap rollbackまたは`dispatchingMove`以降のmigrationがwindow mutationを所有する間、通常event、shortcut Snap、Restore、shared resize、App Constraint計測は新しいframe operationを開始しません。`awaitingNormalDesktopDispatch`は実windowへまだ書き込まないため、通常Desktop観測と既存操作を不必要に遮断せず、dispatch時に共通driverがcontroller状態とgroup構造を再検証します。共通規則は[ASYNC_TRANSACTION_OWNERSHIP.md](ASYNC_TRANSACTION_OWNERSHIP.md)に固定します。
- 待機中の同一Proxy再ドロップは新しいtransactionを生成せず、安定した最新destinationへ既存captureだけを更新します。sourceへ戻した場合は専用の`cancelledAtSource`でdispatch前cancelし、同じmanaged Proxyを退役・再生成せずqueued pixelと選択保留だけを解除します。中央statusのtitleは最大48 pt、副表示は最大18 ptとしてProxy boundsへ自動的に収めます。待機から退役まで表示状態を増やさず、member別番号、managed identity、geometry、orderingは変更しません。
- `GroupSpaceMigrationReservationShadow.swift`は、受理済みcaptureの実memberをMission Control上で識別するPresenterです。capture済みPID + CGWindowIDへ完全一致するlayer 0 surfaceだけを、displayごと最大1枚の`.stationary`・入力透過panelで半透明の黒い影とgroup/FIFO表示として描画します。同一アプリ名、title、近似frameによる代替選択は行わず、重複identityや欠落surfaceはfail closedで描画しません。「移動予約中」は最大26 ptでframeへ適応させます。
- `GroupSpaceMigrationReservationShadowObserver.swift`はこのPresenterだけのsession-scoped read-only observerです。最初の受理済みreservationで起動し、10 Hzの独立timerを所有します。transform判定のdesktop baselineは受理済み`GroupSpaceMigrationCapture`のexact PID + CGWindowID + `sourceFrame`をObserver自身が凍結保持し、Active Space cleanupで消去される`lastGroupWindowServerEvidenceByIdentity`へ依存しません。初回/retargetはnext-turn one-shotから取得を始めますが、pointer down/drag中はtimerだけ維持してWindow Server geometry readを0にします。mouse-up後はexact member framesが1.5 pt以内で3 sample・0.18秒以上静止するまでShadowを復帰させず、OSのretiling animation中へ追従しません。初回だけ2 sample・0.08秒へ短縮します。settle後は全memberをShadow geometryとして更新する処理を止め、各予約group 1枚のexact sentinelだけを10 Hzでprobeし、移動/消失/normal化時にだけfail closedでfull acquisitionへ戻ります。Mission Controlの表示frame取得元は必ず`CGWindowListCopyWindowInfo([.optionOnScreenOnly, .excludeDesktopElements], ...)`とし、exact PID + CGWindowIDによる絞り込みは取得後に行います。`CGWindowListCreateDescriptionFromArray`へ置き換えてはいけません。指定ID descriptionはMission Control compositor上のlive thumbnail geometry取得経路として扱わないためです。application activationやActive Space変更はShadowを即時hideしpending one-shotをcancelする早期lifecycle hintとして扱い、予約scene自体はその場で破棄しません。実際のnormal desktopは専用Observerが凍結baselineから再証明してsceneを閉じます。fade・event tap・専用pointer monitor・burst pollingは持ちません。Observerのgate/stateはtransport、FIFO、cancel、rollback、AX layout、foreground認可から読み取れず、Shadow故障は表示欠落にだけ退化します。
- physical commit後のAX配置は実windowをそのまま更新します。以前の`GroupSpaceMigrationHandoffOverlay`によるfloating snapshot coverは、更新を完全には隠せず逆に一瞬の前面画像を生むため撤去しています。presentation coverをtransportやlayoutの正当性条件にせず、実windowの更新が見える場合はOS/AXの実際のsettlementとして扱います。
- 移送後layoutはsource / destinationのvisible frame比率で投影し、既知App Constraintに違反する場合は既存canonical partitionで調整します。実frameの非重複・接続・画面内収容を満たさない解はcommitしません。

詳細なphase、失敗時の最終状態、非公開APIの確立方法と将来の保守境界は[PRIVATE_API_GROUP_SPACE_MIGRATION.md](PRIVATE_API_GROUP_SPACE_MIGRATION.md)に固定します。

- `SnapController+GroupForeground.swift` は通常desktop clickのWindow Server / AX一致を認可します。Mission Control proxy clickは別の明示認可であり、captured exact group/member集合にだけ束縛して、toggleと同型の全member raiseへ接続します。実windowのfrontmostやplacement frame一致をmutation前に要求しません。
- `ForegroundSelectionMonitor.swift` はWindow Server selectionのbaselineと変化検出だけを所有します。timer、group identity、AXRaise、foreground mode、handle presentationを持ちません。`SnapController+ForegroundSelectionMonitoring.swift` がlong-lived eligibilityとevent/fallback接続を担当し、通常経路はmouse、AX focused/main、workspace activation、Mission Control callbackから即時に動作します。取りこぼしだけを既存1 Hz Recoveryが再観測し、独立した10 Hz loopは存在しません。
- drag / native or shared resize / Assist / Snap / restore / Space transition or migration / owned foreground mutation / stopではselection baselineを失効させます。transaction終了後の最初の観測は非認可baselineであり、transaction前のselectionを新しいユーザー意図として再生しません。
- `RuntimeWindowIDResolver.swift` はunderscored AX WindowID resolverの単一optional boundaryです。Space backendとpointer dragが同じwrapperを共有し、private functionを各機能へ重複実装しません。同一PIDに複数windowがあるpointer dragでは、mouse-down時のCGWindowIDとAX elementのruntime WindowIDが一意一致した場合だけ対象を確定します。resolver失敗はabsenceではなくunknownであり、従来のpublic AX / Window Server geometry-title matcherへfail closedでfallbackします。
- `MissionControlGroupProxy.swift` はMission Control proxy挙動とscopeされたtransition authorizationを担当します。選択確認中はproxyのgeneration、ordering、preview presentationを固定し、Mission Control exit由来のwindow resignまたはActive Space通知では確認をcancelしません。最初の確認時刻0.14秒は維持し、AppKit/workspace frontmost publicationだけが未settleの場合に限り、同じcandidate / group / member / presentation generation / tokenを0.06秒、0.10秒の有限追加観測へ渡します。各遅延callbackは自身のselection generationが現在値と一致する場合だけ候補を継続または終了でき、取消済みcallbackが同じProxy上の新しい選択を閉じません。確認開始時点から通常のselection fallback / desktop click / resize presentation rebuildを停止し、一つのexact候補が成立した時点で他proxyの保留確認とtransition tokenを同じmain-loop turnで失効させます。callback成立後のselected compositeは、Window Serverが選択surfaceを復帰させている途中で構造的に削除せず、最初のexact whole-group orderingを覆うtransaction-owned handoffとしてのみ保持します。
- AX / display / geometryの一時的不確実性によるMission Control presentation suppressionはgroup単位のevidenceから判定します。証明済みtransformはcontroller側の`groupID + member set`に束縛したshort-lived leaseとして保持し、proxy click用selection tokenとは共有しません。未解決・利用不能な観測だけではglobal transform leaseを開始せず、あるgroupのincomplete observationは別groupが証明済みのtransformを取り消しません。fast retryは有限で、未解決のdebtは独立した1 Hz Recovery watchdogで再観測します。
- proxy選択からgroup foreground完了までは`groupID + activation generation + captured member set + preferred member`を所有する一つのtransactionです。Active Space cleanupは確認待ちまたは確定済みactivationのexact groupだけを保存し、unrelated Proxyと通常pending operationを従来どおり破棄します。migration presentation ownershipはこの保存判定へ含めません。各retryは同じexact member全体をraiseし直し、Window Server settlement確認だけが完了条件です。selected compositeはこのtransactionの成功またはcancelでretireし、通常完了より長く表示される場合は0.50秒のfail-safeで透明・noninteractive化します。透明化だけを理由にselection surfaceを遷移途中で`orderOut`せず、最終retireはtransaction所有者が行います。
- Mission Control変形検出のdesktop baselineは`placement.appliedFrame`ではなく、同じPID + CGWindowIDについてAX frameとWindow Server frameが通常desktop上で一致した最後の観測です。片軸だけが変化するshared/native resizeを等方的なMission Control scaleとして認証しません。
- selected proxyの静止compositeは最初のper-window AXRaise列を覆いますが、実window ordering自体は待機させず同じtransactionで実行します。最初のcomplete pass後に限り、証明済みMission Control scaleが残る間は重複AXRaise / focusを受動観測へ置き換えます。normal geometryへ戻った最初のWindow Server orderingが未settleなら1回だけ再観測し、それでも全member frontmostを確認できない場合は既存のwhole-group retryへ戻ります。変形中の縮小配置をfrontmost完了として受理せず、受動観測には既存retry上限と同じ有限上限を設けます。
- selection evidenceはboundedかつgroup-specificであり、stale transition evidenceを後の無関係なaction認可へ再利用してはいけません。
- group labelの番号は`SnapGroupStore`に現在存在する全groupの既存stable sort indexを唯一のsourceとします。通常Proxyの一時的なpresentable subsetや累積`creationOrder`を表示番号へ使わず、通常Proxy、migration reservation、実member shadowで同じordinalを共有します。

## AssistとPreview

- 通常Mission Control CG Preview、Assist、MC transientは同時取得数2のglobal gateを共有します。いずれもbackground threadで最大0.45秒の枠待機を行い、main threadを塞がず、一時的な枠競合とWindow Serverが画像を返さない場合を分離します。枠待機中にNormal Preview / Assistの所有operationがcancelされた場合は、既存`shouldCapture`を物理取得直前に再評価して新しいWindow Server captureを発行しません。これはoperation livenessだけを見る補完であり、HOT/COLD、geometry、Space、AX/Window Serverの追加観測を行いません。MC transientは同じ境界にsession authorizationを重ね、さらに物理transaction最大1本のsingle-flight gateを持ちます。
- `WindowPickerPanel.swift` はcandidate windowを表示します。
- `AXWindowService.previewCGImage` は共有capture admission後にcallerの`shouldCapture`を再評価し、そのrequestがまだ認可されている場合だけWindow Server画像取得へ進みます。Preview設定、Normal/Assist operation liveness、MC transient session authorizationは各ownerが既存の認可情報だけを渡し、service自身は追加観測を行いません。
- Assist候補画像は候補panelが必要としたwindowだけを非同期取得し、0.45秒以内に完了しなければplaceholderを先に表示します。枚数上限は設けず、ユニーク候補数で32 MiBを均等分割して全候補を取得します。遅れて完了した画像は同じpanelへ適用し、一時的な取得失敗は0.18秒、0.55秒の有限backoffで最大3回まで試行します。
- Mission Control画像に定期取得とfreshnessはありません。新規memberの初回、resizeまたはdisplay移動後に同じ最新geometryを2回観測した時、完全なWindow Server evidenceでHOTからCOLD-visibleへの遷移を2回観測した時だけ非同期取得します。geometry確認は最後の変化から0.15秒後のcoalesced one-shotであり、連続resize中に画像取得を試行しません。確認中の位置だけの変化はPID、Window ID、stable identity、display、pixel sizeが一致する限り同じ取得候補として継続し、size/display/identity変更は新しい候補として扱います。1 Hz Recovery watchdogはイベント取りこぼし時に保留済みtriggerを進めるだけで、時間経過から画像要求を生成しません。
- Mission Control previewの要求は物理window単位で最新geometryへ合流し、実行中4件、OperationQueue 8件を上限とします。上限到達時はactiveな待機要求を捨てず、完了ごとに複数displayをround-robinしながら各display内FIFOで次を投入します。COLD/geometry triggerには1秒cooldownを適用しますが、要求自体は保持し、初回取得は待たせません。Assistとの実Window Server取得並列数は引き続きglobal gateで2件です。
- Mission Control / Space / display変形中はdesktop stability gateが全trigger laneを閉じ、実行中結果を世代失効します。通常desktopで再観測されたidentity、display、geometry、per-image budgetが一致するまで完了画像をstagingし、変形途中の縮小・再配置pixelをcacheへ確定しません。
- 例外としてMission Control表示専用のtransient laneを通常Preview cacheから分離します。通常Desktopのcomplete Window Server観測でgroup全体がHOTと証明された場合だけ、そのgroupの全memberをatomicな認可snapshotへ入れます。通常HOT/COLD stateはincomplete evidenceで前状態を保持しますが、その保持HOTはtransient認可へ使いません。Mission Control開始時に可視Space条件と交差させて認可group集合を一度だけ固定し、部分遮蔽groupや一部memberだけの取得・差し替えは行いません。Window Server transformの対象member frameが1 pt以内で同一geometryを2観測・0.08秒以上維持した後だけ一回のsession captureを開始し、Mission Control内または結果適用時にHOT/COLDを再評価しません。通常Preview cache、HOT/COLD、resize/initial triggerへ結果を返しません。
- transient laneは通常Preview byte limitと同額の独立budgetとします。設定UIはnormal + transientの合計上限を表示し、その半分を通常キャッシュ、残り半分をMission Control中だけの一時キャッシュへ割り当てます。初期表示64 MiBは通常32 MiB + transient 32 MiBです。最低1 MiB/memberを基準にsession最大24 member、認可済みgroup plan単位のadmission、display round-robinとします。直接window取得は通常Preview/Assistのglobal gateを共有し、transient transactionも物理的に最大1本です。global gate待機後にもsession generationを再確認して失効済みrequestのCG取得を発行せず、発行済み同期CG取得が戻った後も縮小・再sample前後でgenerationを再確認します。割当targetがnominal寸法を超える場合だけbest-resolutionを要求し、PID + CGWindowID、元windowとの縦横比、byte budgetを再検証して割当以上へ保持・拡大しません。MC終了でlogical generationを即失効し、未選択groupのtemporary pixelsを破棄します。選択済みgroupだけは既存Proxy選択transactionが実window handoffを完了/cancelするまでtemporary pixelsを所有し、その後Proxy retirementと同時に破棄します。
- Preview dataはderived / bounded / disposable stateであり、window identityやplacement correctnessの権威にはなりません。Mission Controlの通常previewは固定720×480 capではなく、現在presentation可能な全memberで通常キャッシュ枠（初期値32 MiB、UI表示上限の半分）を均等共有し、実byte costが割当を超える画像は割当内まで縮小します。現在候補はLRU順では削除せず、OSが画像自体を返さない場合だけicon fallbackを使用します。cacheと最大4件のstaging結果はメモリ内だけに保持し、無効化・機能OFF・終了時に世代を切って破棄します。

## Recovery

Taboraは独立した低頻度Recovery watchdogを維持します。Recoveryはlost mouse-up、Assist cleanup、handle presentation / occlusion recovery、observer re-arm、一時的なAX / Window Server failureに対する安全網です。最新の平常時常駐コストの実測値とWindowServer委託負荷は[PERFORMANCE_VALIDATION.md](PERFORMANCE_VALIDATION.md)に記録します。mouse event monitorはstartup / re-enable時にbounded readiness burstを受け、その後のRecoveryでは1 Hz tickごとに単一のre-arm attemptだけを行います。tickは画像ファイルやディスクを走査しませんが、presentation liveness判定のためWindow Serverのon-screen snapshotを取得します。これは常駐時の主要な定常観測コストであるため、正常時のRecoveryをこれ以上高頻度化したり、制限のない第二global discovery loopを追加してはいけません。 Display消失の新しいrebindも原則はscreen-change通知所有で、0.15 / 0.35 / 0.75 / 1.25秒の有限settlement内で対象groupだけを確認します。それでも未解決なexact candidateだけを最大6秒の期限付きdebtとして既存1 Hzへ渡します。通常tickからmanaged-display topology全体、全groupのSpace membership、画像取得を新規実行してはいけません。
